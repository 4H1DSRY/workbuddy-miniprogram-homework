## 零、三条总原则

后面每一条方案都从这三条推出来，先立规矩：

1. **扩大点击区，不放大视觉。** 热区不足用伪元素或内边距扩，字号、图标、间距的观感一律不动。
2. **区分"文字"和"装饰"两套门槛。** 文字要 4.5:1；分割线、箭头这类非文字只要 3:1。把装饰也按文字标准调，会把整个"淡雅"气质改死。
3. **不调 token 的值，改引用。** 直接把 `--c-ink-4` 的色值调深，全站 19 处一次性变深，页面的层次关系会被抹平。正确做法是**把不该用浅色的地方迁到深一档**。

## 一、P0-1 热区（10 处）

### 手法选择

| 场景 | 手法 | 为什么 |
|---|---|---|
| 嵌在 flex/baseline 行里的文字（切猫、＋添加） | **伪元素撑开** | 加 padding 会改变 baseline 对齐，负 margin 又会牵扯行高 |
| 块级整行（`.foot`） | **伪元素撑开** | 用 `min-height` 会把首页顶出视口（现在 1230/1282，只剩 52rpx 余量） |
| 横向排列的 chip（筛选、猫 chip、性别） | **直接加 padding / min-height** | 垂直方向扩展不影响横向排布，最省事 |
| 独立按钮（删除、空态） | **直接加 padding** | 无相邻元素 |

### 逐条改法

**1. 切猫 `.sw`**（index.wxss:31）

```css
.sw {
  position: relative;
  /* 其余属性不动 */
}
.sw::after {
  content: "";
  position: absolute;
  left: -9rpx; right: -9rpx;      /* 吃掉 18rpx 间距的一半，相邻两个刚好相接不重叠 */
  top: 50%;
  height: 88rpx;
  transform: translateY(-50%);
}
```

**2. 加猫 `.sw-add`**（index.wxss:43）同上，`left/right: -9rpx`、`height: 88rpx`。

**3. 「＋ 添加」`.more`**（app.wxss:104）

```css
.section-title .more { position: relative; }
.section-title .more::after {
  content: ""; position: absolute;
  left: -16rpx; right: -16rpx; top: 50%;
  height: 88rpx; transform: translateY(-50%);
}
```

**4. 「今天 N 条记录」`.foot`**（index.wxss:234）同上，`left: 0; right: 0`。

**5. 筛选 `.filter`**（records.wxss:153）
`padding: 12rpx 26rpx` → **`padding: 25rpx 26rpx`**（25×2 + 24rpx×1.62 ≈ 89rpx）

**6. 猫咪 chip `.cat-chip`**（records.wxss:54）
加 **`min-height: 88rpx`**（现有 `align-items: center` 已经居中，间距不用动）

**7. 性别 `.seg-item`**（cat-edit.wxss:111）
`padding: 10rpx 30rpx` → **`padding: 25rpx 30rpx`**

**8. 删除 `.del-btn`**（cat-edit.wxss:138）
`padding: 20rpx 0` → **`padding: 24rpx 0`**（24×2 + 42 ≈ 90rpx）

**9–10. 空态按钮**（index.wxss:278 / records.wxss:315）
`padding: 20rpx 52rpx` → **`25rpx 52rpx`**；`padding: 18rpx 48rpx` → **`25rpx 48rpx`**

### 副作用与验收

- 伪元素方案**不改任何布局**，理论上零视觉变化。
- padding 方案会让 chip/按钮纵向变高，records 页筛选区、cat-edit 表单区会各长高约 25rpx，需重看一眼滚动长度。
- 验收：改完用真机或模拟器点一遍，特别是切猫标签（两个伪元素相接处不能互相吃点击）。

## 二、P0-2 tabBar 未选中色

`app.json:16` `"color": "#B8B0A6"` → **`"#736A62"`**

实测候选：

| 色值 | 对比度 | 判断 |
|---|---|---|
| #B8B0A6（现状） | 2.02:1 | 不可读 |
| #7A7168 | 4.51:1 | 擦线，不留余量 |
| **#736A62** | **4.99:1** | **推荐** |

## 三、P0-3 灰阶（核心方案：分层 + 迁移）

### 问题本质

不是"色值不够深"，而是**用错了层级**。19 处 `--c-ink-4`（3.58:1）里，大部分承载的是「日期、单位、子标题、页脚说明」——这些是**要读的信息**，不该用装饰级灰度。

### 重排后的六级语义

| 层 | Token | 值 | 对比度 | 用途 | 门槛 |
|---|---|---|---|---|---|
| 主文字 | `--c-ink` | #1E1B19 | 17.13 | 标题、数值、正文 | ≥4.5 ✓ |
| 次文字 | `--c-ink-2` | #4A443F | 9.59 | 标签、列表主文案 | ≥4.5 ✓ |
| 辅助文字 | `--c-ink-3` | #7A7168 | 4.78 | **所有承载信息的次要文字** | ≥4.5 ✓ |
| 装饰 | `--c-ink-4` | #8C8178 | 3.58 | 箭头、图标描边 | ≥3.0 ✓（非文字） |
| 弱装饰 | `--c-ink-5` | #B8B0A6 | 2.02 | 分隔、占位背景 | 不承载信息 |
| 发丝线 | `--c-rule` | #E6E0D6 | — | 分割线 | 非文字 |

**token 值一个都不改**，只改引用位置。这样观感变化是可控的（`--c-ink-3` 本来就在用），不会出现"整页突然变重"。

## 四、P0-4 字号（16 档 → 6 档）

### 映射表

微信六档 22/17/15/14/12pt = 44/34/30/28/24rpx。现状 16 档按下表归并：

| 现值 | 归并到 | 影响面 |
|---|---|---|
| 20, 21, 22, 23 | **24** | 23 处，最大变更 |
| 26, 27 | **28** | 9 处 |
| 30 | **30** | 4 处（保持） |
| 32, 34 | **34** | 5 处 |
| 40, 42 | **44** | 4 处 |
| 52 | 52 | 1 处（头像占位，装饰） |
| 68, 92 | 68 / 92 | 2 处（展示数字，不受六档约束） |

改完后每页档数：

| 页 | 现在 | 改后 |
|---|---|---|
| index | 8 | 6（24/28/34/44/68/92） |
| records | 10 | 4（24/28/30/44） |
| mine | 9 | 5（24/28/30/34/44） |
| cat-edit | 6 | 4（24/28/30/34） |

### 代价（重要）

**这一项会改变版面比例，是全部方案里唯一有视觉风险的操作。**

23 处字号从 20–23rpx 提到 24rpx，单处涨 1–4rpx（0.5–2px）。`index` 页昨天刚压到 1230rpx（视口 1282rpx），只剩 52rpx 余量——字号上调后**很可能重新超出一屏**，四个动作按钮又被折线切掉。

所以：

- 字号必须与**间距压缩**同批做（`margin-top` 逐段减 2–4rpx 找回）
- 或者先出 375 宽的 HTML 对照稿（像上次 `_design/compare.html` 那样），确认版面能装下再动代码
- 改完必须重测首页一屏高度

### 附带修正

`index.wxss:4` 注释「字号只有四层：20/24/68/92」与实现不符，改成：

```
/* 字号：24(注) / 28(正文) / 34(标题) / 44(页标题)，另加 68/92 两个展示数字 */
```

## 五、P0-5 保存防重复

`cat-edit.js:137`。改三处：

```js
data: {
  submitting: false,          // ① 新增提交锁
  ...
}

onSave() {
  if (this.data.submitting) return        // ② 入口拦截
  const checked = store.validateCat(this.data.form)
  if (!checked.ok) {
    wx.showToast({ title: checked.msg, icon: 'none' })
    return                                 // 校验失败不锁
  }
  this.setData({ submitting: true })       // ③ 校验通过后才锁

  const payload = checked.value
  try {
    if (this.data.isEdit) {
      store.updateCat(this.data.id, payload)
    } else {
      const cat = store.addCat(payload)
      if (app.globalData) app.globalData.currentCatId = cat.id
    }
    wx.showToast({ title: this.data.isEdit ? '已保存' : '已添加', icon: 'success' })
    setTimeout(() => wx.navigateBack(), 600)   // 锁保持到页面销毁
  } catch (e) {
    this.setData({ submitting: false })        // 异常必须解锁
    wx.showToast({ title: '保存失败，请重试', icon: 'none' })
  }
}
```

配套 `cat-edit.wxml:102` 加视觉态：

```xml
<view class="save-btn {{submitting ? 'is-busy' : ''}}" bindtap="onSave">
  {{submitting ? '保存中…' : '保存档案'}}
</view>
```

```css
.save-btn.is-busy { opacity: .6; }
```

**关键点**：校验失败时**不能上锁**，否则用户改完字段就再也提交不了。锁只在"通过校验、即将写库"这一瞬间上。

## 六、P1 七项

### P1-1 确认色统一

两处 `confirmColor` 分别是 `#C96A6A`（cat-edit.js:164）和 `#E8763F`（mine.js:75），都不是品牌朱。

**改法**：`confirmColor` 是小程序原生弹窗参数，**读不到 CSS 变量**，必须走 JS 常量——`utils/theme.js` 里已有 `PALETTE.vermilion = '#B5442F'`，两处直接引用：

```js
const { PALETTE } = require('../../utils/theme.js')
// ...
confirmColor: PALETTE.vermilion
```

对比度 5.17:1，作为弹窗确认文字在白底上充足。

### P1-2 渐变语法错

`mine.wxss:5`：

```css
/* 现在：var(--c-paper)6EE 非法，整条声明被丢弃 */
background: linear-gradient(140deg, var(--c-paper) 0%, var(--c-paper)6EE 100%);
```

两端同色的渐变本身没有意义（`.card` 已给了 `background: var(--c-paper)`）。**直接删掉这一行**，不要试图"修好它"——修成两个不同色，等于给用户卡加了个肉眼看不见的渐变，属于无效代码。

### P1-3 校验错误定位字段

好消息：`store.validateCat()` **已经返回 `field`**，数据层是齐的，只是页面没用。

三步：

1. `data` 加 `errorField: ''`、`errorMsg: ''`
2. `onSave` 校验失败时 `setData({ errorField: checked.field, errorMsg: checked.msg })`，并在对应 `bindinput` 里清空该字段的错误
3. `cat-edit.wxml` 顶部加一条公告式提示，对应 field 的行加 `.field--error`

```xml
<!-- 表单顶部 -->
<view class="form-error" wx:if="{{errorMsg}}">{{errorMsg}}</view>
```

```xml
<view class="field {{errorField === 'weight' ? 'field--error' : ''}}">
```

```css
.form-error {
  font-size: 24rpx; color: #B5442F;
  background: #F3E7E2; border-radius: 4rpx;
  padding: 16rpx 20rpx; margin-bottom: 8rpx;
}
.field--error .f-label,
.field--error .f-input { color: #B5442F; }
.field--error { border-bottom-color: #B5442F; }
```

这对应指南 2.3 的「表单顶部告知原因 + 标识出错字段」。

### P1-4 细线 1px → 相对单位

| 位置 | 现在 | 改为 | 理由 |
|---|---|---|---|
| `app.wxss:136` `.hairline` | `height: 1px` | `height: 1rpx` | 纯分隔线，1rpx 在 dpr2 上即 0.5px，更接近发丝 |
| `index.wxss:180` `.bar-track` | `height: 1px` | `height: 2rpx` | 刻度线要可见，2rpx 在 375 宽上正好 1px，且随屏缩放 |

`.bar-fill` 同步改 2rpx。

### P1-5 字号注释修正

见第四节末尾。

### P1-6 两套 token 合一

`--c-text-*` 与 `--c-ink-*` 值完全相同，纯技术债。

**做法**：按"值相同"做批量替换，替换表如下（`app.wxss:38-49` 的兼容段共 11 个变量）：

| 兼容名 | 语义名 |
|---|---|
| `--c-text` | `--c-ink` |
| `--c-text-2` ~ `--c-text-5` | `--c-ink-2` ~ `--c-ink-5` |
| `--c-line` | `--c-rule` |
| `--c-line-soft` | `--c-rule-soft` |
| `--c-line-2` | `--c-rule-strong` |
| `--c-brand` / `-deep` / `-tint` | `--c-vermilion` / `-deep` / `-tint` |

替换完删掉整个兼容段。

风险：`--c-line-2` 对应的是 `--c-rule-strong`（不是 `--c-rule`）——**按名字猜会错**。建议先跑 dry-run 打印「替换前值 / 替换后值 / 文件:行」，逐行确认后再落盘。

### P1-7 色值去重

`utils/store.js:314-323` 的 `TYPE_META` 直接写字面量。改为从 `theme.js` 取：

```js
const { PALETTE } = require('./theme.js')
// color: PALETTE.ink6 / PALETTE.vermilion
```

这样色值只剩两处真源：`app.wxss`（CSS）+ `theme.js`（JS），且已有的一致性校验能覆盖。
