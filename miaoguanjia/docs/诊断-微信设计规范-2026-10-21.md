## 一、结论

**总分 16 / 26**（13 条判定规则，每条 0/1/2）

| 原则 | 得分 | 失分项 |
|---|---|---|
| 友好礼貌 | 5 / 6 | A1（records 页层级模糊） |
| 清晰明确 | 6 / 8 | B2（层级含混）、B4（冗余反馈）、B5（错误不定位字段） |
| 便捷优雅 | 3 / 6 | **C2 热区 0 分**（10 处不达标）、C3 |

一句话：**视觉语言是清醒的，可读性和可点击性是被牺牲掉的。** 设计意图（纸墨朱、留白、唯一焦点）在四页里保持一致，问题集中在两类——字号/对比度为了"淡雅"压过了可读下限，可点击区域为了"精致"压过了 7mm 触控下限。这两类都是局部数值调整，不需要重构。

## 二、P0 严重（影响可用性，建议优先修）

### P0-1　10 处可点击区域低于 7mm（88rpx）

指南 3.2 明确：热区物理尺寸 7–9mm。逐处估算：

| 元素 | 位置 | 构成 | 估算高 | 判定 |
|---|---|---|---|---|
| 切猫 `.sw` | index.wxss:31 | 22rpx 字，无 padding | ≈36rpx | ✗ 最严重 |
| 加猫 `.sw-add` | index.wxss:43 | 26rpx，line-height:1 | 26rpx | ✗ 26×26rpx |
| 「＋ 添加」`.more` | app.wxss:104 / mine.wxml:34 | 22rpx 字，无 padding | ≈36rpx | ✗ |
| 「今天 N 条记录」`.foot` | index.wxss:234 | padding-top 20 | ≈59rpx | ✗ |
| 筛选 chip `.filter` | records.wxss:148 | padding 12×2 | ≈63rpx | ✗ |
| 猫咪 chip `.cat-chip` | records.wxss:54 | padding 8×2 + 头像 52 | 68rpx | ✗ |
| 性别 `.seg-item` | cat-edit.wxss:108 | padding 10×2 | ≈59rpx | ✗ |
| 删除按钮 `.del-btn` | cat-edit.wxss:133 | padding 20×2 | ≈82rpx | ✗ 临界 |
| 空态按钮 ×2 | index.wxss:276 / records.wxss:310 | padding 18–20×2 | 78–79rpx | ✗ |

合格的有：`.save-btn`（≈105rpx）、`.row`（≈135rpx）、`.act`（≈95rpx，勉强）、`.avatar-wrap`（200rpx）。

**影响**：切猫、切筛选是这两个页面的最高频操作，热区只有 26–68rpx，手指点空率显著上升。这正好命中指南说的「不做任何适配直接移植到手机上」。

**修复方向**：不放大视觉，只扩点击层——给容器加 `min-height:88rpx` + `display:flex;align-items:center`，或用伪元素撑开。

### P0-2　tabBar 未选中文字对比度 2.02:1

`app.json:16` `"color": "#B8B0A6"`，在 `#FAF8F4` 上实测 **2.02:1**。

微信 tabBar 文字约 10px，属小字号，WCAG AA 要求 ≥4.5:1。**这是全局导航，影响每一个页面。**

同族问题：选中色 `#1E1B19` 是 16.15:1，两者跨度 8 倍，未选中项几乎"消失"。

### P0-3　两级灰阶文字不可读

实测对比度（背景 `#FAF8F4` / 白卡 `#FFFFFF`，取较优值）：

| Token | 色值 | 对比度 | 判定 | 引用数 | 实际用途 |
|---|---|---|---|---|---|
| `--c-ink` | #1E1B19 | 17.13:1 | ✓ | — | 主文字 |
| `--c-ink-2` | #4A443F | 9.59:1 | ✓ | 10 | 次文字 |
| `--c-ink-3` | #7A7168 | 4.78:1 | ✓ | 4 | 辅助（刚好过线） |
| `--c-ink-4` | #8C8178 | 3.80:1 | ✗ 正文不达标 | **19** | 辅助文字主力 |
| `--c-ink-5` | #B8B0A6 | 2.14:1 | ✗ 不达标 | **10** | 日期、ring-cap、chart-tip、切猫、箭头 |
| `--c-ink-6` | #C9C2B8 | 1.77:1 | ✗ 不达标 | 2 | `.row-arrow`、`.f-arrow` |

`--c-ink-4` 是引用最多的灰阶（19 处），全部落在 22–23rpx（11–11.5px）的辅助文字上。3.80:1 只够"大字号"（≥18.66px 粗体或 24px 常规），小字不达标。

### P0-4　34% 的字号低于 12px

67 处 `font-size` 声明，16 个不同值：

```
20(5) 21(5) 22(11) 23(2) 24(17) 26(6) 27(3) 28(2)
30(4) 32(3) 34(2) 40(3) 42(1) 52(1) 68(1) 92(1)
```

- **<24rpx（12px）共 23 处，占 34%**
- 20rpx = 10px，配宋体（字面小、重心偏上）比黑体更难读
- 微信规范六档：22/17/15/14/12pt；本项目 16 档

最刺眼的一处：`cat-edit.wxss:143` `.footer` 21rpx + `--c-line-2` #DED8CC = **1.34:1**，「资料仅保存在本机，换手机不会同步」这句几乎是隐形的——而这恰恰是需要用户看见的话。

### P0-5　保存档案无防重复提交

`cat-edit.js:137` `onSave` 直接写库再 `setTimeout(navigateBack, 600)`。

- 无 disabled 态、无 loading、无提交锁
- 600ms 窗口内连点两次 → `store.addCat()` 执行两次 → **产生重复猫档案**

「新增」路径会真的写出两条记录。这是全项目唯一会造成数据脏污的问题。

## 三、P1 应修（一致性 / 静默失效）

### P1-1　同一个"破坏性确认"用了两个不同红色

| 位置 | 色值 | 性质 |
|---|---|---|
| `cat-edit.js:164` | `#C96A6A` 粉红 | 删除猫档案 |
| `mine.js:75` | `#E8763F` 橙 | 重置演示数据 |

两个都不是品牌朱（`#B5442F`），彼此也不一致。用户无法通过颜色建立"这是危险操作"的稳定预期——违反 D1 跨页一致。

### P1-2　`.profile` 渐变声明语法错误（静默失效）

`mine.wxss:5`：

```css
background: linear-gradient(140deg, var(--c-paper) 0%, var(--c-paper)6EE 100%);
```

`var(--c-paper)6EE` 不是合法颜色值，整条声明被浏览器丢弃。因为 `.card` 已有 `background: var(--c-paper)`，视觉上看不出来——属于**不报错、不生效**的静默 bug。

### P1-3　表单校验失败不定位字段

`cat-edit.js:140` 校验失败只 `wx.showToast({ title: checked.msg })`。

指南 2.3 要求：表单报错要在**表单顶部告知原因并标识出错误字段**。当前实现用户只看到一句飘过的提示，回到表单后不知道该改哪一项（4 个输入项、2 个选择项）。

### P1-4　细线用固定 1px

- `app.wxss:135` `.hairline { height: 1px }`
- `index.wxss:180` `.bar-track { height: 1px }` / `:190` `.bar-fill { height: 1px }`

1px 在 3x 屏上是 3 物理像素，比设计意图粗，且不随屏宽缩放。项目其余分隔线用的是 `1rpx`，两种混用。

### P1-5　字号层级失控，且注释与实现不符

- `index.wxss:4` 注释写「字号只有四层：20(注) / 24(标签) / 68(名字) / 92(数值)」，实际文件里有 **8 档**（多出 22 / 26 / 32 / 40）
- `records.wxss` 10 档、`mine.wxss` 9 档、`cat-edit.wxss` 6 档
- 出现 21 / 23 / 27rpx 这类"只差半档"的值，无法说明为什么是 23 不是 22

这不是"品牌需要有更多层级"，而是逐处微调累积的结果。

### P1-6　两套 token 命名并存

`app.wxss` 同时定义语义名（`--c-ink-*`）与兼容名（`--c-text-*`），值相同。现状：

- index 页用 `--c-ink-*`
- records / cat-edit / mine 仍大量用 `--c-text-*`

值一致所以不出错，但改一处配色要改两处，且新人无法判断该用哪套。注释里自认是"历史页面还在引用"——技术债已确认，只是没还。

### P1-7　颜色有了第四份拷贝

`utils/store.js:314-323` 的 `TYPE_META` 里写字面量 `#C9C2B8` / `#B5442F`。

现有三处同源：`app.wxss`（CSS 变量）、`utils/theme.js`（JS 常量）、`utils/store.js`（记录类型色）。前两处有校验保护，第三处没有。

## 五、**不算问题**的偏离（别改）

这部分最容易被机械套规范改坏，单独列出：

| 偏离项 | 为什么不算缺陷 |
|---|---|
| 不用微信绿 `#07C160` 作主色 | 指南只要求"统一稳定"，不强制品牌色。纸墨朱是完整自洽的品牌系统 |
| 卡片圆角 8rpx（规范 16rpx） | 视觉语言选择，与"直角切割、去阴影"一致 |
| 无 WeUI 组件 | 全自绘且规格自洽，不违反任何条款 |
| 92rpx / 68rpx 大数字 | 展示型排版，非正文，不受六档限制 |
| `.bar-track` 1px 细线做刻度 | 线长即完成度的设计，本身成立——问题只在"用了 px 而非 rpx"，见 P1-4 |
| 首页一屏信息密度高 | 一屏读完是刻意设计，层级清晰，不违反 A1 |

## 六、自动化扫描原始结果

```
BLOCK 0 · WARN 42 · INFO 19

WARN R1 ×42   字号不在微信六档阶梯内
INFO  C3 ×19  <image> 未开启 lazy-load
```

交叉验证：67 处 `font-size` 声明中，落在 44/34/30/28/24rpx 的有 25 处（24×17 + 28×2 + 30×4 + 34×2），其余 42 处被命中，与分布统计完全吻合。

两点说明：

1. **R1 的 42 条按设计意图不成立**——本项目有意走自定义 token 与宋体排版，微信六档不强制。这条只作参考，不折算进评分（见第五节）。
2. **R4（热区）脚本未命中**——`bindtap` 与 `class` 的匹配受模板语法干扰（`class="seg-item {{...}}"`），静态解析拿不到干净类名。P0-1 的 10 处热区结论来自人工逐条读 wxss 估算，不是机器输出。
