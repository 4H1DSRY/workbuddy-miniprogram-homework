## 零、一句话结论

**在个人主体下，两个 AI 功能都无法通过审核；折中方案（就诊描述生成器 + 预设形象换装）可以把两件事都做出来，且不需要云开发、不改现有架构。**

关键区分——**技术上能做 ≠ 审核能过**。个人主体的云函数完全能调大模型 API，代码跑得通，卡在提审环节。下面所有"不可行"都指审核不可行。

## 一、四条路径可行性

| | A 换主体 | B 规则引擎诊断 | C 只做演示 | **D 折中（已选）** |
|---|---|---|---|---|
| 技术可行 | ✓ | ✓ | ✓ | ✓ |

| AI 诊断（给病名） | ✓ | ✓ | ✓ | ✗ |
| AI 生图卡通化 | ✓ | ✗ | ✓ | ✗ |

### 各路径卡点明细

**A 换主体**
- 个体工商户能否算"企业主体"开深度合成 —— **未确认，需向微信客服核实**；若只认公司，则须注册有限公司。
- 深度合成类目资质三选一：微信云开发 `extend.AI`（最简，可下载《深度合成服务在用证明》）／第三方模型备案 + 盖章合作协议 + 在用证明／自研模型算法备案（2–4 个月）。
- 医疗侧：「宠物医院/兽医」类目个人不可从事，企业主体需《动物诊疗许可证》。**若只做健康记录不做诊疗，仍可能被判定为问诊**，存在不确定性。

**B 规则引擎诊断**
- 不调大模型 ≠ 不需要类目。「在线问诊」是按**功能实质**判定的，不是按技术实现。填症状 → 出结论，即使规则是硬编码的，也属问诊。
- 所以 B 不能解决个人主体的类目问题，只是绕开"深度合成"这一道关，仍有第二道关。

**D 折中（已选）**
- 彻底不碰医疗判断、不碰生成式 AI，走「工具」或「生活服务 - 宠物（非医院类）」。

## 二、D 方案的功能边界（红线清单）

这张表决定能不能过审，比任何设计都重要。

| 功能 | ✅ 可以做 | ❌ 不可以做 | 措辞红线 |
|---|---|---|---|
| 症状记录 | 多选症状、持续时间、食欲/饮水/排泄状态 | 根据症状输出可能疾病名 | 禁用「诊断」「确诊」「疑似」「病症判断」 |
| 就诊描述生成 | 把已选症状拼成一段结构化文字，供用户复制给兽医 | 由大模型生成分析、建议、结论 | 输出物只能是「事实陈述」，不能是「判断」 |
| 分级提示 | 「建议尽快就医 / 可先观察并记录」 | 「你的猫可能患有 XX」 | 分级依据必须写明是「记录完整度」而非「病情严重度」 |
| 知识展示 | 静态科普卡片（如「猫每天正常饮水约 40–60ml/kg」） | 针对当前症状给治疗方案 | 必须标注「科普内容，不构成医疗建议」 |
| 形象换装 | 预置形象 + 换色/换配饰 + 点按反馈 | 上传照片生成新形象 | 禁用「AI 生成」「智能生成」 |

### 必须落地的三处合规文案

1. **入口页固定提示**（不是弹窗、不是角落小字）：`本工具仅记录症状并生成就诊描述，不提供诊断或医疗建议`
2. **结果页底部**：`以上内容由你填写的信息整理而成，请以执业兽医的判断为准`
3. **首次使用**：一次性说明「数据仅保存在本机」

这三条本身就是设计元素，会占版面——这是后面"一屏策略"要重算的原因之一。

## 四、对现有设计系统的冲击

这是决定"修复要不要等"的核心表。

| 现有修复项 | D 方案下的影响 | 处理 |
|---|---|---|
| 热区 10 处 | 无影响，新页面同样要 88rpx | ✅ 照做 |
| tabBar 对比度 | 无影响 | ✅ 照做 |
| 保存防重复 | 无影响，新页面复用同一套提交锁 | ✅ 照做 |
| 灰阶迁移 | 无影响，但**要顺手预留语义色** | ✅ 照做（附加） |
| token 合并去重 | 无影响 | ✅ 照做 |
| 细线 1rpx | 无影响 | ✅ 照做 |
| **字号收口 16→6 档** | **新页面引入新层级**（大结论句、症状标签、报告正文） | ⏸ 等新页面定稿 |
| **首页一屏策略** | **照片区变交互入口**，1230/1282 的余量算法作废 | ⏸ 重算 |

### 需要新增的语义色（灰阶迁移时顺手补）

现在色板只有「朱」一个强调色，而新功能至少需要三态：

| 语义 | 建议 | 对比度 |
|---|---|---|
| 提示/正常 | 现有 `--c-ink-2` | 9.59 ✓ |
| 关注/观察 | 新增 `--c-warn`（橙，需与朱区分） | 待定 |
| 紧急/就医 | 现有 `--c-vermilion` | 5.17 ✓ |

**风险点**：纸墨朱的体系里「朱 = 唯一焦点」，再加一个橙色会和它抢注意力。要么把「朱」固定给"紧急"、把"焦点"让给墨色；要么新增色只用于小面积徽标。这个要在做灰阶迁移之前定，否则会返工。

### 会被推翻的三处文案

「数据仅保存在本机」出现在 `index.wxml` footer、`mine.wxml` footer、`cat-edit.wxml` footer。D 方案不需要云，**这三处文案全部继续成立**——这是 D 相对 A 的一个隐性收益。若将来做云同步，三处要同时改。

## 七、附：判断依据

- 宠物类目个人主体限制：微信官方《小程序备案服务内容标识选择指引》，「宠物医院/兽医」「宠物医疗服务平台」「其他宠物健康服务」均标注"个人主体不可从事"。
- 深度合成类目仅企业主体可申请：腾讯云开发者社区《应用商店与小程序平台对 AI 功能的审核标准与应对策略》。此为服务商口径，**建议在 mp 后台"添加类目"处实测确认**。
- AI 生成内容标识：《人工智能生成合成内容标识办法》（2025-09-01 施行）要求显式 + 隐式双重标识。D 方案不生成 AI 内容，不涉及。
