## 二、症状记录页

### 结构

```
[导航栏] 记录症状
────────────────────────
当前：团子 · 3 岁 6 个月          ← 一行，说明给谁记

┌ 免责条（常驻，不可关闭）───────┐
│ 本工具仅记录症状并生成就诊描述，   │   ← caution 底色
│ 不提供诊断或医疗建议。           │
└───────────────────────────┘

[ 说不上来，但感觉不对劲 ]        ← 快捷项，猫主人的直觉常早于症状清单

用自己的话说                      ← 主角，在选项之前
找不到对应的选项、或者说不清是什么，都写在这里。
[____________________________________]

或者从下面勾选，可多选             ← 选项降级为提示

[ 误食 / 接触有毒物 ]              ← 与「说不上来」并列的快捷入口

精神与活动   没精神/不爱动 · 躲起来不出来 · 烦躁易怒 · 半夜乱叫/叫声变多
吃喝         食欲下降 · 完全不吃 · 食欲变好/总讨食 · 喝水变多 · 喝水变少 · 体重下降
皮肤与被毛   理毛变少/毛乱 · 局部掉毛 · 频繁抓挠 · 皮肤发红/结痂 · 皮屑增多
吐与排便     呕吐 · 干呕/吐毛球 · 腹泻/软便 · 便秘 · 便中带血或发黑
排尿         频繁进猫砂盆 · 蹲很久尿不出 · 尿量变多 · 尿里带血 · 猫砂盆外乱尿
呼吸与鼻子   打喷嚏/流鼻涕 · 咳嗽 · 张嘴呼吸 · 呼吸声变重
眼睛与耳朵   眼部分泌物 · 眼睛红/睁不开 · 耳朵有异味 · 频繁挠耳甩头
口腔与牙齿   流口水 · 口臭 · 吃饭偏头/掉食 · 只敢吃软食 · 牙龈出血
走路与动作   走路不稳/转圈 · 后腿无力/拖行 · 跛行/不愿跳 · 抽搐
（每组末尾均有「其他…」）

持续多久
[1 天内] [2–3 天] [一周内] [更久]   ← 单选

[ 生成就诊描述 ]                ← 底部主按钮，吸底
```

### 分组依据

**9 组、42 项。分组顺序照兽医问诊的系统回顾**：一般状态 → 消化 → 泌尿 → 呼吸 → 眼耳 → 口腔 → 皮肤 → 神经骨科。

完整的疾病谱映射、每一项对应的疾病、以及数据来源，见 **`症状清单依据-2026-10-22.md`**。那份文档回答"为什么清单里必须有这一项"，本文档只定义界面。

三条硬约束：

| 约束 | 理由 |
|---|---|
| 每组 3–6 项 | 少于 3 项显得敷衍，多于 6 项要换行三次，扫读变慢 |
| 必须成对出现方向 | 「喝水变多 / 变少」「食欲下降 / 食欲变好」——只列单向会整类漏掉疾病。甲亢与糖尿病的典型表现是"吃得多却掉体重"，只列"食欲下降"就等于看不见它们 |
| 带限定词 | 「**频繁**吐毛球」而非「吐毛球」；「**蹲很久**尿不出」而非「排尿异常」 |

**为什么从 8 组扩到 9 组（第二轮修订）**：第一版凭常识分组，漏掉了神经与骨科（后腿无力/抽搐/跛行）、被毛状态（理毛变少是 CKD/甲亢/口腔疼痛的共同信号）、以及所有"反向"表现。这些不是补充项，是整类疾病在清单里的唯一入口。

### 交互规则

- **自由描述前置**：先写再说。选项放在后面，避免选项先入为主地框定用户去观察什么（closed-ended 问卷的引导性偏差）。
- **多选 chip**：选中 = 墨底白字（复用 `.filter.on`），未选中 = 纸白底 + 墨字。
- **「其他…」与选项视觉区分**：虚线边框，表示"这不是一个预设答案"。
- **热区**：chip 视觉高度保持细窄，点击层 ≥88rpx（沿用热区伪元素方案）。
- **单选组**（持续时长）：选中态与多选一致，但只能选一个。
- **按钮可用条件**：勾选了任意一项 **或** 自由描述框非空。二者其一即可提交——否则等于强制用户用选项表达。
- **不要求一屏装完**：这是表单页，允许滚动；但**主按钮吸底**，任何时候可见。

### 为什么不按「严重程度」排序症状

不按"轻重"排，也不给红旗项加视觉标记。按轻重排、或把「便中带血」标红，等于在暗示哪些更危险——那就是诊断。

红旗项只存在于**分级判定的后台规则**里，不出现在界面上。

## 三、就诊描述页

### 结构

```
[导航栏] 就诊描述
────────────────────────
已整理 6 项症状                  ← 事实陈述，不是结论

┌ 分级提示（三态）──────────────┐
│ ⚠ 记录中有 2 项建议尽快就医的症状  │   ← alert 或 caution 底色
│   依据：症状数量与持续时间        │
└───────────────────────────┘

┌ 描述正文（可复制）─────────────┐
│ 【猫咪信息】                   │
│ 团子 · 3 岁 6 个月 · 英国短毛猫   │
│ 近期体重 4.62 kg，7 天内下降 0.12 kg │   ← 从数据层自动带，用户不用填
│                             │
│ 【勾选的症状】                 │
│ · 没精神 / 不爱动              │
│ · 食欲下降                    │
│ · 呕吐                       │
│                             │
│ 【你描述的】                   │   ← 与勾选地位相同，不是"备注"
│ 今天一直趴在沙发底下不出来，      │
│ 叫它也不应。晚上吐了一次，        │
│ 是没消化的猫粮。                 │
│                             │
│ 【持续】2–3 天                 │
│                             │
│ 以上信息由主人自行记录，          │
│ 未经兽医确认。未列出的情况可能      │
│ 同样重要，请一并向兽医说明。       │
└───────────────────────────┘

[ 复制描述 ]      [ 完成 ]        ← 主 + 次
```

### 三段式而非"症状清单 + 备注"

「勾选的症状」和「你描述的」分成两段、地位相同，是为了让读报告的人知道：**这两类信息的可靠性不一样，但都不可省略**。

如果把自由描述降级成"备注"，等于告诉兽医"这段可以不看"。

### 分级判定的实现口径（关键）

分级不是按"症状轻重"排，是**按时限排**（分诊 triage 的逻辑）。判定依据必须写出来，否则等于在暗示"病情轻重"。

| 档 | 触发项 | 界面文案 |
|---|---|---|
| **急诊** | 蹲很久尿不出、张嘴呼吸、抽搐、后腿突然拖行、误食/接触有毒物、完全不吃超过 24 小时（肥胖猫） | 「请立即就医」 |
| **急** | 便中带血或发黑、持续呕吐、眼睛突然睁不开、症状持续一周以上 | 「建议今天或明天就诊」 |
| **常规** | 其余 | 「可先观察，继续记录」 |

**为什么"蹲很久尿不出"排第一**：公猫尿道阻塞 24–48 小时可致死，是所有项里时间窗最短的。

**为什么"完全不吃"是急诊级**：肥胖猫禁食 2–3 天即可触发肝脂质沉积——这是猫特有的机制，比狗危险得多。

红旗项是**预置清单**，不是模型判断，且**不在症状页做任何视觉标记**。分级结果旁必须标「依据：症状数量与持续时间」，让人知道这只是规则判定。

### 复制

`wx.setClipboardData` + `wx.showToast({ icon: 'success' })`（1 档轻量成功）。不弹模态。

## 四、入口设计

### records 页底部入口（不是首页）

首页内容已 1230rpx / 视口 1282rpx，只剩 52rpx 余量。再加一行必然破一屏。

而且症状记录是**低频高价值**功能（猫不舒服时才用），不该占首页黄金位。

```
records 页 footer 之上：

[ 身体不适？记录症状                › ]
   ↑ 一条淡边框的整行，caution 色文字，热区 ≥88rpx
```

### cat-edit 加「形象」分组

```
〔新增分组，放在「喂养参数」之后〕

形象
  当前形象    [英短·戴围巾]  ›      ← 点开选择器
  主色        [●][●][●][●][●]      ← 5 个预设色点
```

形象 = 8–12 个预置 SVG/CSS 组合（品种轮廓 × 配饰 × 主色），**本地渲染，零生成**。

### 首页照片区的微交互

`.photo` 保持 300rpx 高度不变（不动一屏），但：
- 可点击 → `wx.vibrateShort` + 形象轻微缩放（`transform: scale(0.98)` 120ms）
- 长按 → 弹出「去换形象」

这样"可互动"成立，但不新增任何页面和区块。

## 五、字号层级（第三批的依据）

微信六档 22/17/15/14/12pt 正好对应下面 5 档，另加 2 个展示数字。

| Token | rpx | pt | 用途 | 现有 16 档中的归并来源 |
|---|---|---|---|---|
| `--font-caption` | 24 | 12 | 注释、标签、chip、副文案 | 20 / 21 / 22 / 23 / 24 |
| `--font-body` | 28 | 14 | 正文、选项、描述 | 26 / 27 / 28 |
| `--font-subtitle` | 30 | 15 | 分组标题、卡片标题 | 30 |
| `--font-title` | 34 | 17 | 列表主文案、页面内标题 | 32 / 34 |
| `--font-display` | 44 | 22 | 页面大标题 | 40 / 42 |
| `--font-num-lg` | 68 | — | 展示数字（名字） | 68 |
| `--font-num-xl` | 92 | — | 展示数字（体重） | 92 |

**新页面只用前 5 档**，不引入新值。这样第三批一次收口，新页面直接对齐。

### 关于「朱」的渐进收窄

按已确认的语义（朱 = 紧急/就医），第三批时建议：

| 现有用朱处 | 处理 | 理由 |
|---|---|---|
| 首页照顾分环 | **保留朱** | 低分确实表示"需要留意"，属提醒 |
| 体重 delta `↑` | **保留朱** | 体重上涨对猫是负面信号 |
| `latest-num`（最新体重） | **改墨色** | 纯展示，不是提醒 |
| `.pill` 徽章 | 保留 | 与 `--c-alert-bg` 同色系，语义一致 |

只改一处，观感变化最小。

## 六、三态色的使用边界

| Token 对 | 只用于 | 不用于 |
|---|---|---|
| `--c-alert-*` | 红旗症状提示、必须就医 | 删除按钮、错误提示（用朱字即可，不必铺底） |
| `--c-caution-*` | 免责条、观察档 | 主按钮、强调数字 |
| `--c-safe-*` | 正常档 | 不用绿色（纸墨朱体系里没有绿） |

**不建议引入绿色表示"健康"**——整个体系只有纸、墨、朱三色，加绿会破坏。正常档用次墨（`#4A443F`）+ 浅纸底即可。

## 七、合规文案的三个锚点

| 位置 | 文案 | 形式 |
|---|---|---|
| 症状页顶部 | 本工具仅记录症状并生成就诊描述，不提供诊断或医疗建议 | 常驻条，不可关闭 |
| 报告页分级卡 | 依据：症状数量与持续时间，仅供就诊沟通使用 | 分级卡内小字 |
| 报告页正文末 | 以上信息由主人自行记录，未经兽医确认 | 描述正文的一部分（复制时一起带走） |

第三条尤其重要：**描述被复制到兽医那里时，免责声明要跟着走**。
