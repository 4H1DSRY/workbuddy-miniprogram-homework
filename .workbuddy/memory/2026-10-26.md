# 2026-10-26 · 喵管家：可选用量 + 超量提醒

## 1. 需求与判断
用户新提：喂食超量弹提醒、喂食克数做成可选、喝水同理。

- 「喝水同理」只按「数量也别写死」理解，**没有**顺延成「喝水超量也劝阻」——
  猫多喝水不是问题，限制饮水才是错的。饮水超参考量只告知，文案指向
  「连续几天都多就把记录带给兽医看」，不写病名。
- 逗猫顺手一起改成可选用量（三个都是数量型动作），但超量不提醒。
- 提醒不硬拦：`仍然记录 / 先不喂` 两选一，取消时面板保持打开。

## 3. 两个必须记住的坑
- **`wx.showModal` 的 content 不认 `\n`**：折成空格，代码里排好的断行在屏幕上是一片。
  文案改成每句能独立读完的话，靠自然折行。
- **在 `onShow` 里调 `wx.showModal` 会让模拟器启动失败**（`Error: simulator launch failed`）。
  当时为了截图自测，在 onShow 末尾加了两行 openSheet+onSheetConfirm，连续三次重开都起不来；
  删掉后一次就正常。截图验证要用别的方式，别在生命周期里弹窗。

## 4. 顺手发现的真问题
- 三条刻度封顶 100%，**超量在进度条上完全不可见**（480/260 与 260/260 画得一样长）。
  所以超量提醒只能写在面板里。`simulate.js` 三条「百分比自洽」断言补 `Math.min(100, …)`。

## 5. 截图/点击自动化（可复用）
- 桌面被 WorkBuddy 窗口盖住时，`SetForegroundWindow` 不够，要先
  `SetWindowPos(HWND_TOPMOST)` → `SetForegroundWindow` → `SetWindowPos(HWND_NOTOPMOST)`。
- **不要靠肉眼量 `Read` 出来的截图坐标**（会缩放）。用 rpx 数学反推：
  手机机身宽（图像像素）/ 375 = 每 CSS px 的图像像素，再按 `48 + 88.8*(i-0.5)` 这类式子算。
  这次 `投食` 中心算成 image(1315, 1011)，一次点中。
- 检查颜色不要靠眼睛：GDI `GetPixel` 采一块区域取众数。借此确认
  `wx.showModal` 的 `confirmColor` 在模拟器里**不生效**（仍是 #0B5C9A 默认蓝）。
